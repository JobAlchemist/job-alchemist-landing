# SEO Audit: JobAlchemist

**Site:** https://www.jobalchemist.tech/

**Audited:** 2026-07-26

**Business type:** SaaS / job-application software

**Validated SEO health score:** **73/100**

## Executive summary

JobAlchemist has solid crawlability, complete server-rendered content, valid canonicals, a useful sitemap, strong homepage copy, and good mobile rendering. No critical indexing or penalty-level issue was found.

The highest-confidence opportunities are:

1. Enforce HTTPS. The HTTP homepage currently returns the full page with status 200.
2. Replace oversized, one-size PNG delivery with responsive AVIF/WebP assets.
3. Strengthen the small resource library with deeper, attributed, evidence-led content.
4. Replace deprecated `HowTo` schema and consolidate fragmented Organization entities.
5. Align internal links with canonical URLs and keep sitemap dates accurate.

The deterministic Codex SEO runner initially scored the site 74/100. Specialist validation adjusted this to 73/100 and rejected several false or overstated findings. In particular, the generated “Lighthouse” values were formulas, not observed Lighthouse or CrUX measurements.

## What is already working

- Homepage, robots.txt, sitemap.xml and all 11 sitemap URLs return HTTP 200.
- Every HTML page has a canonical URL and exactly one H1.
- Critical copy, metadata and JSON-LD are present in initial HTML; indexing does not depend on JavaScript.
- Homepage metadata is strong: 52-character title and 147-character description.
- Homepage content is comprehensive and specific, with 2,400+ words, a clear workflow, pricing, comparison table, screenshots, testimonials and detailed FAQs.
- Mobile screenshots show the H1 and primary CTA above the fold with no overlap, overflow or horizontal scrolling.
- The site allows standard and AI search crawlers and serves a substantive `/llms.txt`.
- All 14 JSON-LD blocks parse successfully.
- All rendered homepage images have relevant alt text. The automated “weak alt” finding came from an empty hidden modal image and is rejected.

## High-priority findings

### 1. HTTPS is not enforced

Verified responses:

- `http://www.jobalchemist.tech/` → `200`, no redirect
- `http://jobalchemist.tech/` → `301` to the insecure `http://www...` URL
- `https://www.jobalchemist.tech/` → canonical destination

Enable **Enforce HTTPS** in GitHub Pages and verify both HTTP variants reach the HTTPS canonical in one permanent redirect. Canonical tags help consolidate duplicates but are weaker than redirects.

References: [GitHub Pages HTTPS](https://docs.github.com/en/pages/getting-started-with-github-pages/securing-your-github-pages-site-with-https), [Google redirects](https://developers.google.com/search/docs/crawling-indexing/301-redirects).

### 2. Image delivery is the clearest performance opportunity

The three main landing images total **5,770,740 bytes**:

| Asset | Bytes |
|---|---:|
| `landing-solution-fit-analysis.png` | 1,997,966 |
| `landing-problem-workspace.png` | 1,928,235 |
| `landing-hero-uncertainty.png` | 1,844,539 |

The 1.84 MB hero is delivered at 1823×863 even when rendered around 358×269 on mobile. There are no `<picture>`, `srcset` or `sizes` candidates, so every viewport receives the original.

Create responsive AVIF/WebP variants, retain a fallback, and art-direct the mobile hero crop. A cautious expected saving for the three large images is roughly 3.5–4.6 MB, subject to visual-quality review.

The three proof screenshots total 951,920 bytes and load eagerly near page start. Serve small responsive thumbnails with `loading="lazy"` and `decoding="async"`, retaining full-resolution files only as modal/link targets.

### 3. Organic resource coverage is thin

Approximate visible word counts, excluding navigation/footer:

| Page | Words |
|---|---:|
| Resource hub | 146 |
| How to improve a CV for ATS | 201 |
| JobAlchemist vs ChatGPT | 203 |
| How to analyse a job ad | 227 |
| Job-search glossary | 543 |

These pages are valid and indexable, but the guides provide limited original evidence, examples, sourcing, author context and topical depth compared with the intent they target.

Expand the guides around real user tasks rather than a word-count target. Add worked examples, primary sources, author/reviewer details, visible publication/update dates, internal links, and a clear connection to the product workflow.

## Medium-priority findings

### Canonical URL reinforcement

`/index.html` and `/resources/index.html` return 200 while canonicalizing to `/` and `/resources/`. Internal navigation repeatedly links to `index.html` forms. Update internal links to canonical URLs. Where hosting permits, redirect duplicate index URLs.

Reference: [Google canonical guidance](https://developers.google.com/search/docs/crawling-indexing/consolidate-duplicate-urls).

### Deprecated and fragmented schema

- Both guide pages use deprecated `HowTo` markup.
- Commercial `FAQPage` markup is valid vocabulary but no longer a meaningful Google rich-result tactic.
- The homepage defines two Organization entities, only one with a stable `@id`.
- Sitewide Organization details are repeated rather than consistently referenced.

Replace the two `HowTo` graphs with truthful `Article` or `BlogPosting` markup containing author, dates, publisher and image where supported by visible content. Consolidate the Organization entity around one stable `@id`.

Reference: [Google HowTo/FAQ change](https://developers.google.com/search/blog/2023/08/howto-faq-changes).

### Visible expertise and methodology

The About page provides a credible founder story and relevant experience, but this authority is not visible on the homepage or resource articles. Testimonials are role/location-attributed rather than independently verifiable.

Add:

- A concise “Built by” block linking to About.
- Visible authorship and update dates on resource pages.
- A 140–160 word answer-first section explaining how job-fit assessment works, including evidence mapping, uncertainty, limitations and human review.
- Named, consented case studies or methodology notes where available.

### Metadata cleanup

Titles outside the preferred display range:

- `About JobAlchemist` — 18 characters
- Resources hub — 68 characters
- ATS guide — 70 characters
- Glossary — 70 characters
- Students — 64 characters

These are not indexing failures. Rewrite them only where a shorter version improves intent clarity and click appeal. The Terms description is 98 characters but is low commercial priority.

### Sitemap hygiene

The sitemap is complete, canonical-only, HTTPS-only and valid. Several `lastmod` values predate later repository changes, including the homepage. Update them only when page content materially changes. Remove `<priority>` and `<changefreq>` if desired; Google ignores them.

Reference: [Google sitemap guidance](https://developers.google.com/search/docs/crawling-indexing/sitemaps/build-sitemap).

### Mobile hit areas

Layout quality is good. Several controls are smaller than the comfortable 44–48 px target, especially the 38×30 menu toggle and 8×8 carousel dots. Enlarge hit areas without changing the visible dot size.

## AI-search and SXO observations

- Full content is server-rendered and AI crawlers are allowed.
- `llms.txt` is substantive, but its page list uses plain URLs rather than Markdown links with descriptions; the file also starts with a BOM.
- No sourced original statistics or methodology passages were found.
- Exact-brand visibility is emerging, with limited independent entity signals outside the site and LinkedIn.
- “Job fit assessment” produced a fragmented but mostly transactional result set. JobAlchemist is partially aligned, though competitors often expose an immediate checker or sample result.

The strategic SXO opportunity is a no-login sample report, prefilled example, or lightweight fit-check experience. This is a product/conversion experiment, not a prerequisite for fixing technical SEO.

## Performance caveat

Do not treat the generated values of performance 72, LCP 1.73s, INP 158 ms or CLS 0.15 as measurements. The installed runner generated them with `heuristic_lighthouse()` after PageSpeed data was unavailable:

- LCP was calculated from HTML size, response time and script count.
- INP was calculated from script and stylesheet counts.
- CLS was calculated from missing image dimensions.

No genuine CrUX, PageSpeed, Search Console or GA4 data was available. Collect field p75 LCP/INP/CLS through Search Console, CrUX/PageSpeed credentials, or carefully configured real-user monitoring before making CWV claims.

## Audit limitations

- No Google Search Console, GA4, PageSpeed API, Moz, Bing Webmaster or DataForSEO credentials were configured.
- Search-result sampling was not a locale-controlled Google export.
- No keyword-volume, difficulty, backlink-authority or actual AI-citation dataset was available.
- Performance evidence proves payload size and browser behavior, not representative field CWV.
- Scores are prioritization aids, not predictions of ranking outcomes.
